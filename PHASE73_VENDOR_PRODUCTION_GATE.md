# Phase 73: Final Vendor Production Gate

## 1. Complete Runtime Trace
The complete execution of the Vendor Automation feature follows this trace:
1. **Invoice Upload**: `POST /files/upload` (MIME/Size validated, Checksum calculated, saved to local disk).
2. **Storage**: `Document` record created in PostgreSQL.
3. **OCR**: `POST /ocr/process/:fileId` triggered, `OCRCoordinator` reads file buffer, extracts text.
4. **AI Extraction**: `InvoiceExtractor` uses Gemini/Azure to parse fields.
5. **InvoiceCandidate Creation**: Record created in DB with status `EXTRACTED`.
6. **Vendor Slip Queue**: Job dispatched to `vendor-slip-queue`.
7. **Confidence & Matching**: `VendorSlipWorker` invokes matcher, drops to `MANUAL_REVIEW_REQUIRED` on failure.
8. **Ledger Mapping & Intelligence**: `VendorIntelligenceService` and `LedgerMappingEngine` resolve the expense ledger.
9. **Voucher Builder**: Worker dispatches payload to `voucher-builder` queue.
10. **VoucherCandidate Creation**: `VoucherBuilderEngine` constructs `VoucherCandidate` using `PurchaseStrategy`.
11. **ERP Sync Queue**: Payload queued to `tally-sync`.
12. **Tally Master Validation**: `ProcessERPSyncUseCase` evaluates masters against `TallyDiscoveryReport`.
13. **XML Builder**: If valid, `TallyXmlBuilderService` creates Tally-compatible XML.
14. **HTTP Transport**: Transmitted to local Tally instance.
15. **Audit**: `AccountingDecisionAuditService` logs every rule and decision evaluated.

## 2. Repository Blockers
A rigorous scan of the repository for placeholders, mocks, and hardcoded variables returned **TWO CRITICAL REPOSITORY BLOCKERS** that exist directly in the `vendor-slip-queue` production execution path:

1. **Hardcoded Vendor Ledger**:
   - File: `apps/backend/src/modules/vendor-slip/queue/vendor-slip.worker.ts`
   - Issue: `const vendorLedgerName = 'Sundry Creditors Default';`
   - Impact: Completely ignores the actual Vendor's configured ledger name, forcing all vendor credits into a single faked account.

2. **Hardcoded Expense Ledger**:
   - File: `apps/backend/src/modules/vendor-slip/domain/services/index.ts`
   - Issue: `ExpenseAllocator.allocate` returns `[{ ledger: 'Purchase Account', amount: total }]` marked with an `// (implementation note)`.
   - Impact: Overrides the dynamically resolved `expenseLedgerName` generated by the `LedgerMappingEngine`. Every invoice is forcefully booked against 'Purchase Account' regardless of its true nature.

These hardcoded values prevent true dynamic accounting.

## 5. Failure Verification (Safe Recovery: YES)
- **OCR/AI Failure**: Caught by exception handlers, API returns 500/400. Document safely sits in `UPLOADED` state.
- **Confidence Too Low**: Caught by `ExpenseValidationPolicy`, gracefully transitions to `MANUAL_REVIEW_REQUIRED`.
- **Vendor/Ledger Unmapped**: Caught by Matcher/MappingEngine, gracefully transitions to `MANUAL_REVIEW_REQUIRED`.
- **Missing Tally Master**: Caught by `TallyMasterValidationEngine`, job transitions to `MANUAL_REVIEW`, triggering Approval Workflow.
- **Tally Offline/HTTP Timeout**: Caught by `TallyTransportService`, BullMQ handles retry with exponential backoff up to `maxAttempts`.
- **Redis/Worker Restart**: BullMQ persists jobs in Redis. Abrupt shutdown leaves job active, which is re-acquired upon restart.

---

## 6. Security
- **File Upload**: Strict 10MB size limit and explicit MIME type whitelist (`ALLOWED_MIMES = pdf, png, jpeg, jpg, tiff`).
- **Duplicate Prevention**: SHA-256 checksum calculated and enforced on upload.
- **Authentication**: `JwtAuthGuard` enforced on endpoints.
- **Authorisation**: Fine-grained `PermissionsGuard` (e.g., `Invoice.Read`, `Invoice.Process`) enforced.
- **XML Injection Protection**: `TallyXmlBuilderService` invokes strict `escapeXml()` replacing &, <, >, ", ' to prevent injection.

---

## 7. Performance
- **Volume**: Asynchronous BullMQ decoupled architecture natively supports 100-1000+ invoices/day without blocking the main HTTP thread.
- **Concurrency**: `WorkerHost` handles jobs concurrently based on BullMQ config.
- **Memory**: Buffers are written to disk (`LocalStorageProvider`) before processing, minimizing RAM footprint.
