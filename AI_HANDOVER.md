## 1. Repository Overview
TallyMe Enterprise is an **accounting automation platform** that processes Vendor Invoices (via OCR) and Student Fee payments (via Gmail), extracting data, applying matching logic, generating vouchers, and syncing them directly to Tally Prime (ERP) via its port 9000 XML API.

**Tech Stack**:
- Backend: NestJS, Prisma, PostgreSQL, Redis, BullMQ, Socket.IO
- AI: Gemini Vision (OCR), Gemini API (Extraction), Azure Form Recognizer (fallback)
- Frontend (Primary): `apps/frontend` (Next.js 16)
- Frontend (Secondary): `apps/web` (Next.js 15)

---

## 2. Architecture Summary
The system revolves around TWO mandatory pipelines and ONE shared accounting engine:

1. **Vendor Slip Pipeline**: 
   `POST /ocr/process/:fileId` -> `OcrPipelineService` -> `OcrWorker` -> `VendorSlipWorker` -> `VoucherWorker` -> `ERPConnector`
2. **Student Fee Pipeline**: 
   Gmail notification -> `StudentFeeWorker` -> `VoucherWorker` -> `ERPConnector`

**Constraint**: All accounting must pass through `VoucherBuilderModule`. Do not duplicate voucher logic.

## 4. Critical Constraints & Zero-Trust Rules
1. **PRODUCT_CONSTITUTION.md**: This is the absolute law. Read it. Do not violate the two-pipeline + shared-engine rule.
2. **Zero-Trust**: Never trust previous documentation or claims. Verify everything with runtime logs, Git history, or actual code execution. Do not mock core services (Gemini, BullMQ, ERP) to force a passing test.
3. **No Mocks in Prod Validation**: You cannot declare a feature production-ready if you mocked the OCR, DB, or Queue.
4. **Idempotency**: All BullMQ jobs use IDs (`fileId`, `candidateId`, `eventId`). Do not remove these.
5. **No Direct Sockets from Services**: `OcrPipelineService` MUST NOT inject `EnterpriseEventGateway`. Use domain events -> Worker -> Gateway.
