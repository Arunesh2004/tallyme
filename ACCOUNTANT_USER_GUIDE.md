# TallyMe Enterprise — Accountant User Guide

## Overview
Accountants use TallyMe Enterprise to review extracted invoices, approve or reject OCR results, verify student payment allocations, and monitor ERP sync status.

---

## Uploading Vendor Invoices

1. Navigate to **Vendor Review** (`/vendor-review`)
2. Click **Upload Invoice** (top-right)
3. Select a PDF, JPG, or PNG file (max 5MB)
4. The system will automatically:
   - Run OCR extraction
   - Extract invoice fields (number, date, vendor, amounts)
   - Match against the vendor master
   - Route to review if confidence < 70%

---

## Reviewing OCR Extractions

Documents in `MANUAL_REVIEW_REQUIRED` appear in the review queue with:
- **Extracted Fields**: Invoice number, date, GSTIN, total amount
- **Confidence Score**: 0–100%. Below 70 requires manual verification
- **Source Text**: Raw OCR output for comparison

**Action:** Compare extracted fields against the source document. If correct → **Approve**. If wrong → **Reject** and re-upload with better quality scan.

---

## Approving / Rejecting Invoices

| Action | When to Use | Effect |
|---|---|---|
| **Approve** | Extraction is correct | Document moves to `APPROVED` → ERP sync queued |
| **Reject** | Extraction is wrong | Document marked `FAILED` → audit log created |

---

## Student Payment Verification

1. Navigate to **Student Review** (`/student-review`)
2. Review items flagged as `MANUAL_REVIEW_REQUIRED`
3. Each item shows:
   - Parsed payment amount and reference
   - Matched student (name + enrollment number)
   - Match confidence score
   - Fee allocation breakdown
4. If match is correct → **Approve Match**
5. If match is wrong → **Override Match** → search and select correct student

---

## Voucher Approval Workflow

Vouchers are auto-generated by the backend after approval. Accountants can:
- View pending ERP sync jobs at `/erp-monitoring`
- See XML payloads (read-only) for audit purposes
- Trigger manual retry if a sync job stalled (ADMIN escalation required for permanent failures)

---

## Tally Migration Approval

When the system proposes creating new ledgers or groups in Tally:
1. Navigate to `/tally-migration`
2. Review the **Diff Preview** showing what will be created/modified
3. Click **Approve Migration** to execute

> ⚠️ Rollback requires accountant verification and may require manual correction in Tally Prime.

---

## Handling Manual Review Items

Items land in manual review when:
- OCR confidence < 70%
- Student match confidence < 80%
- Duplicate payment detected
- Amount mismatch between payment and outstanding fee

**Resolution Steps:**
1. Open the item in the review queue
2. Check source document vs. extracted data
3. Correct if needed using the override fields
4. Approve or reject with a reason

---

## Troubleshooting Failed Vouchers

| Symptom | Likely Cause | Resolution |
|---|---|---|
| ERP sync stuck in PENDING | Tally Prime offline | Check `/system-health` → Tally status |
| Voucher marked FAILED_PERMANENT | Tally rejected the XML | View XML payload in ERP monitoring; check ledger names |
| Invoice stays in MANUAL_REVIEW | Confidence too low | Re-upload higher quality scan |
| Student not matched | Student not in master | Add student to master database first |
